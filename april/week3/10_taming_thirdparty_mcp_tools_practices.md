# Taming Third-Party MCP Tools: 5 Practices for Making Agentic Tools Actually Work

## 5 Intuitive Takeaways

- **Third-party tools fail out of the box because their descriptions are generic by design — they serve every use case, so they're optimized for none** — Playwright's MCP server ships 21 tools with descriptions like "Press a key on the keyboard" and "Resize the browser window." These descriptions are correct but useless for guiding an agent through your specific workflow. The agent doesn't know to prefer the accessibility snapshot over a visual screenshot, or that it should always call one tool before another. Without tailoring, the agent hallucinates URLs, navigates to made-up pages, and produces wrong verdicts. The tools work; the descriptions don't tell the agent how to use them for your task.

- **Curate by subtraction, then wrap with domain-specific descriptions — fewer tools with better instructions beats more tools with vague ones** — first, remove tools the agent doesn't need (drag, resize, execute JavaScript in browser) to shrink the context window and reduce decision surface. Then wrap the remaining tools with enhanced descriptions that encode your workflow knowledge: "Before calling browser_click, always call browser_snapshot first to understand the page layout." The new tool is functionally identical to the original — same code, same invocation — but the description now contains your hard-won operational knowledge about what sequence of actions actually works.

- **Deterministic guardrails intercept tool calls before execution for security-critical operations — the agent gets a corrective message, not a crash** — for sensitive operations (like where screenshots are saved in a multi-tenant system), inject validation logic between the agent's tool call and the actual execution. If the agent tries to save a file outside the allowed directory, the guardrail blocks execution and returns an agent-facing message: "Access denied. Save to this path instead." The agent retries with a valid path. This is not prompt-level guidance (which agents can ignore) — it's deterministic code that physically prevents the wrong action while keeping the agentic loop alive.

- **Compose new tools from existing tools to give the agent distinct behavioral options for different contexts** — the same underlying "take screenshot" tool can be wrapped into two separate tools: a general-purpose snapshot tool and an "evidence capture" tool with different descriptions. The evidence tool tells the agent to include the ticket number in the filename and to use it specifically when capturing final verification screenshots. The agent now has a semantic distinction between "take a quick screenshot to understand the page" and "capture formal evidence for the review record" — same code underneath, different behavioral guidance on top.

- **Some operations should bypass the agent entirely — call the tool functions deterministically before handing control to the agent** — login flows with JWT tokens, API authentication, and environment-specific setup are too sensitive, too predictable, and too failure-prone to leave to agentic decision-making. Extract the relevant tool functions from the MCP server and call them as plain functions in your code before the agent loop starts. The agent receives a logged-in browser session and instructions to proceed — it never sees credentials, never attempts login, and never wastes context tokens on a step that has zero agentic value. Reserve agentic reasoning for tasks that actually benefit from it.
