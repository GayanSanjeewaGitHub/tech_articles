# CORAL: Multi-Agent Evolution Through File Systems, Not Weight Updates

## 5 Intuitive Takeaways

- **The LLM weights are completely frozen — all "learning" happens in the file system around it** — CORAL (from MIT, Stanford, Meta, Microsoft, etc.) runs N identical agents in parallel, each with its own Git worktree, but none of them update the model weights. Instead, agents write textual artifacts into a shared persistent file system: attempts (JSON logs of function evaluations keyed by commit hash), notes (markdown files where agents write hypotheses about the search space), and skills (reusable code modules abstracted from successful runs). Learning is entirely through in-context memory accumulation — the agent constructs its next prompt by querying the file system with bash commands. This is a gradient-free search algorithm operating at inference time, not training time.

- **The shared file system IS the communication topology — agents coordinate implicitly by reading and writing, not by messaging** — there's no explicit agent-to-agent communication protocol. A hidden `coral-public` directory is symlinked to all agents, containing attempts, notes, and skills visible to everyone. When Agent 3 discovers a promising approach, it writes notes and commits code. Agent 7 reads those notes during its orientation phase and builds on them. Coordination is emergent from filesystem conventions, not orchestrated by a central planner.

- **The heartbeat protocol solves the local-minima trap with two escape mechanisms** — an asynchronous background runtime interrupts agents with interval triggers (e.g., every 10 evaluations, force the agent to synthesize raw notes into abstracted skills — creating a new starting point outside the current gravitational well) and plateau triggers (when progress stalls, command the agent to attempt a mathematically orthogonal approach). This is structurally identical to thermal noise injection in simulated annealing — a controlled perturbation to escape local optima. The entire agent instruction set, including the heartbeat prompts, is written in deterministic markdown templates.

- **Everything is deterministic templates on the outside, probabilistic reasoning on the inside — and the tension is the point** — the CORAL markdown file gives agents explicit step-by-step orientation: read the task, check the leaderboard, inspect top attempts, search for prior art, read other agents' notes, check available skills. The workflow is rigidly defined (plan → edit → eval → repeat). But the execution of each step depends entirely on the LLM's probabilistic interpretation of natural language instructions like "think creatively" or "build a mental map of what's known." The system's intelligence is bounded by the LLM's frozen semantic understanding — you're asking a model that can't learn from this process to synthesize novel hypotheses in domains like theoretical physics.

- **The cost structure reveals the real constraint: a 3-hour single-agent run costs up to $60 on Claude Opus, scaling linearly with agent count** — four parallel agents for one task can cost $240. With no human in the loop, no LLM-as-judge, and purely programmatic reward functions (graders that return 0 or 1), the system can run indefinitely if you can pay for it. But the paper's "beautiful results" come from hours or days of running with cherry-picked outcomes — the unreported runs that didn't converge are the hidden cost. This is the fundamental trade-off of ADI (Advanced Deterministic Intelligence): you avoid expensive model retraining but pay per-inference costs that compound with every agent, every heartbeat cycle, and every failed exploration.
